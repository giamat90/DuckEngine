Task: 2-7. Class 2 (SIMD, `unsafe`) with a governance step: the entry for `simd/neon.rs` in `gates/unsafe-budget.toml`, declared by the owner in the session on 2026-11-01 ("Declare governance now").

## Summary verdict

Ready for the owner, with one fact stated up front: **the NEON tests have never run.** There is no AArch64 CPU and no emulator on this machine. The backend is cross-compiled and linted for `aarch64-unknown-linux-gnu`; the equivalence with the scalar reference is argued from the instruction semantics (reviewed independently) and is **not run on hardware**. 0 open blocker, 0 open major.

## What the change does

- New `engine/base/src/simd/neon.rs`: `neon::F32x4`, the same operations as `sse2::F32x4`, behind `cfg(all(target_arch = "aarch64", target_feature = "neon"))`. `min`/`max` are a compare and a select (`vcltq`/`vcgtq` + `vbslq`), because `fmin`/`fmax` return NaN for a NaN operand and order the zeros, which the scalar rule (`other` when equal or unordered) does not. No `vfmaq`, `vmlaq`, `vrecpe`, `vrsqrte`.
- `simd/mod.rs`: `F32x4` is the NEON backend on AArch64, SSE2 on x86-64, scalar elsewhere.
- `gates/unsafe-budget.toml`: `neon.rs`, 16 lines (the tool counts 16; the whole budget is 71 of 8,695 code lines, 0.82%).
- Docs: core-runtime (table row, class diagram, backend-choice flowchart, `unsafe` notes), platform-ports row 2-7, README v0.63.

## Findings

- Minor, `unused_unsafe` could fire on intrinsics that are safe for a baseline feature: the aarch64 clippy run with `-D warnings` is clean on Rust 1.94.1, so the `expect(unsafe_code)` is fulfilled and nothing warns.
- Minor, README header version: v0.63 chosen because `develop` is at v0.61 and `main` already holds v0.62 (card 2-8); the clash is avoided when `main` is merged into `develop`.
- Minor, the figure 71 / 8,695 / 0.82% comes from the unsafe-budget tool run on this branch.
- Equivalence assumes the default floating-point control state (flush-to-zero and default-NaN off); the reviewer confirmed this is the default on Linux, Windows and macOS ARM64. Simulation jobs set and assert it (digest section 5).

## Not verified

- Any execution on AArch64 (hardware or emulator). Every claim of bit-identity with the scalar reference rests on instruction semantics.
- Miri does not cover this module (it is compiled out on x86).
- No benchmark on ARM64.
