## What the change does

- `engine/base/tests/alloc_counting.rs`: two integration tests. (1) Two threads are inside `count_allocations` at the same time (a `Barrier` holds them together) and each sees exactly its own counts: all four counters (allocations, one reallocation, deallocations, bytes), with different block counts (3 and 50). (2) A new thread starts with zero allocations, reallocations and bytes.
- `wiki/architecture/core-runtime.md` (the "cross-thread isolation is not tested" note becomes "tested", with the mutation evidence) and README v0.21.
- Not changed: any source file, any gate or protected path. This is the follow-up promised by card 1-1 and enabled by card 1-4 (`allow_in_tests`).

## TDD / evidence

- The tests pass at once because the counters are thread-local, so the red evidence is by mutation (temporary edits of `alloc.rs`, reverted, not committed): sharing any one of the four counters across threads fails the first test; sharing `allocations` or `bytes_requested` also fails the second. Sharing `deallocations` passes the second by design (std makes the new thread free blocks its parent allocated, so a fresh thread legitimately counts deallocations).
- 60 repeated runs green; fmt, clippy (`-D warnings`) and the whole workspace test run green; arch-check passes with threads in `tests/` (uses the 1-4 exemption); wiki lint 0 violations, digest check agrees.
