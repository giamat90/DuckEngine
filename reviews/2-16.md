## Summary

The phase 2 exit criterion "engine/game swap-diff = 0 (port files excluded, N-4) when the second OS adapter lands" had a rule but no tool. This card adds the tool, its config and the first measurement.

## What the change does

- `tools/swap-diff/swap_diff.py`: counts the files that differ between two git revisions and classifies each (adapter, composition root, ports, plumbing, non-code, engine/game; first match wins). Exit 1 when engine/game files exceed `max_engine_game_files`. Port files are reported as a port revision and never fail the check.
- `gates/swap-diff.toml`: the limit (0) and the class globs.
- `tools/swap-diff/test_swap_diff.py`: 27 tests (classification, globs, report, config validation, a temp git repository, option-looking revisions, unicode paths, the real config).
- `.github/workflows/ci.yml`: one step runs the tool's unit tests, like the other tools. The tool itself is not a `ci` gate yet (owner, scope option 1).
- `wiki/architecture/ports-and-adapters.md` (text, Mermaid), README v0.69.

## Findings (independent review)

- Major, fixed: argument injection and a fail-open result. A base or head that began with `-` was read by git as an option (`--output=file` wrote a file and printed OK). Now such a value is refused, and each revision is resolved with `rev-parse --verify --end-of-options <rev>^{commit}` and the diff runs on the two SHAs. Tests added.
- Major, fixed: the `ports` glob covered the whole `platform/src`, so std and Null implementations could change without ever failing. Narrowed to the port declarations and contract files; `headless.rs`, `memory_files.rs`, `std_files.rs`, `vpath.rs` and the tests now count as engine code. The two real measurements are unchanged.
- Minor, fixed: a range with no adapter or composition-root file passed with all zeros. It now fails ("proves nothing"), and the output prints the two resolved commits.
- Minor, fixed: tests added for unicode and space paths, regex characters in globs, the port-revision line, the vacuous range, and a test that sorts known real paths with the real config.
- Minor, documented: two-dot semantics, `gates/**` as non-code, root plumbing files ignored, "inside the rule" softened to an owner's count.

## Not verified / known limits

- It cannot see how many port revisions a port had before; the owner counts (printed on every run).
- `clock.rs`, `files.rs`, `threads.rs` and `window.rs` hold a port and its std or Null implementation together; the tool cannot separate them, so a change to them is reported as a port revision and never fails.
- Any edit to the root `Cargo.toml` and `Cargo.lock` is ignored as plumbing (a dependency bump included).
- `gates/**` is non-code; harmless while the tool is not a gate, to be revisited if it becomes one.
- A range that spans unrelated work (for example NEON in the middle of the GLFW commits) reports that work as engine/game files; ranges must be chosen per card.
