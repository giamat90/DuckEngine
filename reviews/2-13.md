# Review 2-13: unsafe-budget entry and `pending` flag for simd/neon.rs (governance)

Task: 2-13. Class 3 (`gates/unsafe-budget.toml`). The `neon.rs` code itself was reviewed in card 2-7 (`reviews/2-7.md`) and is not part of this diff. Loops: 1 of 3.

## Why this card exists

The release PR #95 (`develop` into `main`) failed the `gates` job: the unsafe-budget tool runs from a checkout of `main`, and `main` did not list `engine/base/src/simd/neon.rs`. Because the trusted configuration comes from `main`, a PR can never add a new unsafe file and its entry together (tried first in this PR: ci run 41337553326 failed with `unsafe-outside-allowlist` although the entry was in the tree). The order is therefore forced: the entry first (this card), the file afterwards (the release PR).

## Decision

The owner chose the recommended option (2026-11-01): an optional `pending = true` flag on a budget entry. With it, `stale-allowlist` is not raised for that entry; the line budget still applies once the file exists.

## What changes

- `tools/unsafe-budget/unsafe_budget.py`: `Budget.pending`, `pending` parsed as a bool (anything else is an error), stale check skips pending entries.
- `tools/unsafe-budget/test_unsafe_budget.py`: 4 new tests (red first: 2 failed for the missing feature).
- `gates/unsafe-budget.toml`: the neon entry with `pending = true`.
- `wiki/architecture/core-runtime.md` (text and Mermaid), README v0.67.


## Known transient

None any more: the `pending` flag keeps `main` green until the release PR brings `neon.rs`. Follow-up: a small PR removes `pending = true` after the release.

## Findings (independent review)

- No blocker, no major. The flag is not a loophole: a pending entry whose file exists is held to the line budget, SAFETY comments and the ratio; a file with `unsafe` and no entry is still `unsafe-outside-allowlist`.
- Minor, fixed: a misnamed redundant test replaced by a real one (pending entry for another path); tests added for `pending = false`, a pending file within budget, a stale sibling next to a pending entry; long line extracted into `_stale_findings`; the Mermaid block moved out of the bullet list and given the release and follow-up steps; this file's stale claims corrected.
- Minor, accepted: while the flag is set the entry stays allowed even if the file never lands; the budget bounds any file that appears. A forgotten flag is not detected by the tool: follow-up card 2-15 removes it after the release.
