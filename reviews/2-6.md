Independent review (fable, read-only): 0 blocker, 2 major, 9 minor. Fixed:
- Major: a second `GlfwWindows` in one process shared GLFW's global state and `glfwTerminate` of one would free the other's windows. A process-wide flag (`OnlyOne`) now refuses the second `load` (`QueueFull`); a test checks the first keeps working.
- Major: Windows DLL planting through the current directory or `PATH`. A bare name is loaded with `LOAD_LIBRARY_SEARCH_DEFAULT_DIRS`; a full path also gets `DLL_LOAD_DIR`. The environment variable is documented as a trust boundary (module doc, wiki, `THIRD_PARTY.md`).
- Minor, all fixed: Linux `native_number` lint (cross-clippy for `x86_64-unknown-linux-gnu` is clean); `load_default` keeps the most telling error and uses `var_os`; `DUCK_REQUIRE_GLFW=1` makes a missing device fail the tests; weak pump test replaced; real callback path tested (real resize, real close click); `version_ok` split into a pure function with a test; setters typed per callback so a wrong pairing does not compile; a window with no slot is destroyed instead of leaked; `GlfwWindows` is explicitly not `Send`; `compile_error!` outside Windows and Linux; docs corrected (function count, version range, `pump` can stay in GLFW while a window is dragged, events outside `pump` are not queued).
- Accepted as is: `InvalidPath` is reused as "invalid argument" for a title with a NUL byte or a zero size (already documented on the port).

Checks (local, Windows): fmt; Clippy pedantic `-D warnings` clean for `x86_64-pc-windows-msvc` and `x86_64-unknown-linux-gnu` (all targets); with GLFW 3.4 and `DUCK_REQUIRE_GLFW=1`: 25 unit tests and the allocation test pass; without the library the same pass with the device tests reporting "not run". `platform` tests unchanged and green. Mutation (cargo-mutants 27.1.0, `lib.rs`, `glfw.rs`, `dynlib.rs`, with the DLL): 122 mutants, 87 caught, 19 unviable, 16 missed. The 16, by cause: 9 are in code compiled only on Linux (`dlopen` wrappers, `glfwGetX11Window`, its number conversion), so the Windows run cannot see them; 2 are the `|` of the Windows search flags (the DLL loads either way, only the dependency lookup differs; no fixture with a dependency); 1 is `Api::scale -> 1.0` (this desktop is at 100%, so the value is equal); 3 are `Api::focused` (depends on desktop focus, which a background session cannot take); 1 is `version_ok -> true` (needs a GLFW older than 3.3; the version rule itself is tested as a pure function).
Not run locally: Linux (type and lint checked only), Miri (the unsafe is FFI), coverage, benchmarks, CI.
