# Review 2-4: window system, events and the Headless window system

Task: 2-4. Class 2 (new port). In `engine/platform`: `IWindowSystem`, `WindowDesc`, `WindowInfo`, `NativeToken`, `Event`, `Action`, `EventQueue`, `PumpResult` (module `window`); `HeadlessWindows` and `ScriptHandle` (module `headless`); `Caps::has_window`, `Platform::windows`, `with_windows`, `headless_windows`; contract suite `window_contract`. `base` became a normal dependency of `platform` (handles and the ring). Section 12 of `wiki/architecture/platform-ports.md` with a Mermaid class view, README v0.59.

Owner choices applied: O6 (events pulled into a caller-owned fixed-capacity queue that reports drops), O7 (lifecycle and input are event kinds of one port).

TDD: the first test (a full queue refuses and keeps order) failed to compile against the missing `window` module (red), then the types were written; contract self-tests against broken systems and the mutation run drove the rest.

Deviations from the design sketch, both recorded in section 12: `pump` takes `&mut EventQueue`; the Headless system has virtual windows (`has_window` true) instead of none, so the contract suite and window logic run without a display. Gamepad events are left out of v0.

Independent review (fable, read-only, run by the coordinator): 0 blocker, 1 major, 11 minor. Everything below was fixed unless stated.
- Major: `IWindowSystem: Send` is wrong for GLFW (window calls on the main thread only). `Send` removed; the module and section 12 say the port is used from the thread that created it and that a `Platform` holding one is not `Send` (clock, threads unchanged). Nothing needed `Send`.
- `window_contract`: after slot reuse the stale id is checked for info, token and destroy; a headless test forces the same slot (new generation, same index).
- The bound checks no longer depend on scripted events: repeated `pump` into a capacity-1 queue (`len == before + delivered`, never above capacity) runs without `feed`; the doc says the order and drop checks are weaker without `feed`.
- Doc on `Resized`: framebuffer size and DPI scale come from `window_info`, events may follow with the GLFW card (not added now). Modifier bits are now `window::mods::{SHIFT, CONTROL, ALT, SUPER}`; scancodes are hardware keys, layout-independent codes come with the input module (phase 7).
- Docs: the caller must check `PumpResult::dropped`; `CloseRequested` stays latched in `window_info` and cannot be cancelled in v0; events of a destroyed window may still be queued and consumers tolerate stale ids; `QueueFull` is the capacity-exhausted error for windows; section 12 and `platform.rs` module doc updated.
- Headless: state changes apply even when the event is dropped (doc and test); zero width or height is refused with `InvalidPath` (test, contract row, broken-system test); `native_token` is never 0 (packed value plus one, `NativeToken::NULL` named and documented).

Checks (local, Windows): fmt; Clippy pedantic `-D warnings` clean with and without `contract-tests`; `platform` tests green (50 unit, 2 + 1 counting-allocator integration tests). Mutation (cargo-mutants 27.1.0): first run on the whole crate, 79 mutants: 49 caught, 3 timeouts, 24 unviable, 3 missed; one fixed with a test (`pump_is_bounded`, broken system `Liar`). After the review fixes, a run on `window.rs` and `headless.rs` only: 44 mutants, 31 caught, 1 timeout, 11 unviable, 1 missed. The miss (and `StdClock::sleep` `<` to `<=` from the first run, not re-run) are equivalent: in `native_token` the generation is shifted to bits 32-63 and the index fills bits 0-31, so `|` and `^` give the same value.
Not run locally: Miri (no unsafe), Linux (CI-only), branch coverage (nightly), line coverage.
