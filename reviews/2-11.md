# Review 2-11: GLFW adapter on Linux under xvfb (governance)

Task: 2-11. Class 3 (CI workflow), goes to `main` first with a hand-started `ci` run. One small ordinary fix of the adapter goes to `develop` as a second PR of the same card (the crate exists only on `develop`).
Loops: 1 of 3.
Reviewer: independent read-only subagent (general-purpose).

## Summary verdict

Ready for the owner. 0 open blocker, 0 open major. Evidence that the Linux half of the phase 2 exit criterion holds: on a hosted `ubuntu-latest` runner, under `xvfb`, with the Ubuntu package `libglfw3` 3.4-4, the real GLFW adapter passed its 21 unit tests (including the window contract suite) and the no-allocation test, with `DUCK_REQUIRE_GLFW=1` (a missing library or display fails, it does not skip).

## What the change does

- New job `glfw_linux` at the end of `.github/workflows/ci.yml` (Ubuntu only, on `main` and by hand): installs `xvfb` and `libglfw3`, runs `xvfb-run --auto-servernum cargo test -p adapter_window_glfw --locked`.
- Guard: `main` is behind `develop` and has no adapter crate. If the folder `engine/adapter_window_glfw` is absent the job writes a notice and a line in the run summary ("not run") and skips the two later steps. If the folder exists, `cargo pkgid` must succeed or the job fails.
- Two workflow tests, `ci-diagrams.md` (Mermaid, six jobs), README v0.64 (v0.63 is used by card 2-7 on `develop`).
- Second PR, into `develop`: `token_of` in the adapter tests gets `#[cfg(windows)]` (only a Windows-only test uses it; on Linux it is dead code and `-D warnings` fails).

## Findings from running on Linux

- One: the dead-code helper above. No Linux-only code path of the adapter (X11 native token, library name `libglfw.so.3`, events) needed a change; the tests cover them (native token test, real resize, contract).

## Findings

- Major, the guard treated any `cargo pkgid` failure as "crate absent" (a broken manifest in the release batch would have gone green): fixed, presence comes from the folder and a cargo failure then fails the job; test added.
- Major, a skipped job was almost invisible: fixed, the "not run" line is also written to the run summary; the owner is told here that on `main` this job reports "not run" until `develop` is merged in.
- Minor, `ubuntu-latest` moves: the probe ran on a runner image whose package was `libglfw3` 3.4-4; the version is printed in the log (`dpkg-query`), and the adapter accepts 3.3 up to the end of 3.x. Not pinned.
- Minor, `apt-get update` has no retry: accepted.
- Minor, the test slice assumes `glfw_linux` is the last job or the next job key has no hyphen: accepted (same pattern as card 2-8).
- Minor, README v0.64 after v0.62: v0.63 is card 2-7 on `develop`.
