## Summary verdict

Ready for the owner. No blocker. The independent review found one major (counter overflow could panic inside the allocator); it is fixed and covered by tests. Minor findings fixed. One acceptance criterion is not met in `base` (cross-thread isolation test), see "Deviations".

## What the change does

- `engine/base/src/alloc.rs`: `CountingAllocator<A: GlobalAlloc>` counting allocations, reallocations, deallocations and requested bytes per thread (const-initialised thread-local `Cell`, no destructor, saturating arithmetic, never panics); `AllocCounts` (`calls`, `since`); `current_counts`, `count_allocations`.
- `engine/base/tests/alloc_counting.rs`: the allocator installed as `#[global_allocator]`; zero-allocation tests including `Logger<NullSink>` (0 calls) vs `Logger<MemorySink>` (> 0), which closes the gap left open in 1-1.
- `engine/base/Cargo.toml`: leaves the workspace lint table (it forbids `unsafe`) and repeats it with `unsafe_code = "deny"` and `undocumented_unsafe_blocks = "deny"`, the pattern of `skeleton-unsafe`. `alloc` is the only module with `#![expect(unsafe_code)]`.
- Design note and decisions: `wiki/architecture/core-runtime.md` section 8.

## Deviations from the card

- **Cross-thread isolation test dropped.** Card criterion: "a second thread's allocations are not counted". `gates/architecture.toml` forbids creating threads in `base` (arch-check flagged `thread::scope`), and a waiver is not allowed. The property holds by construction (a thread-local) and is stated in the design note; the test moves to the first crate allowed to spawn threads, or to a governance change.

## Not verified

- **Miri on the Windows host target:** the integration test binary reports undefined behaviour inside the standard library's own Windows allocator (`sys/alloc/windows.rs`, over-aligned header read, triggered by the test harness's cache-padded channel), under Stacked and Tree Borrows. The wrapper forwards the pointer unchanged. The unit tests are Miri clean on the host. The reviewer did not re-run the host case.
- Miri, mutation and a release-profile test run are not in CI (workflow files are protected); the numbers above are from a local run.
- `cargo deny` is not installed locally (no dependency was added). Linux was run only through Miri's Linux target, not natively.
- Local `arch_check.py` on the working tree reports unlisted crates because of a leftover git worktree `.wt/1-2` (branch `agent/1-0-allocator-policy`, not created by this task); on a clean export of the commit it is clean. The directory is not mine and was not touched.
