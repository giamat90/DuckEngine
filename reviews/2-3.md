# Review 2-3: file system port (read-only, virtual paths, polled background reads)

Task: 2-3. Class 2 (new port, new dependency edge, concurrency). In `engine/platform`: `VPath` (module `vpath`); `IFileSystem`, `ReadId`, `ReadState` (module `files`); `MemoryFileSystem` (Null implementation, module `memory_files`); `StdFileSystem` with one lazily started I/O thread (module `std_files`); `Platform::files`, `with_files`, `Caps::has_background_io`; contract suite `files_contract`. `base` became a normal dependency of `platform` (handles and pool; an L1 to L0 edge). Section 11 of `wiki/architecture/platform-ports.md` with a Mermaid class view, README v0.60.

Owner choices applied: O4 (read-only, virtual paths, caller-owned buffers), O5 (polled background reads, no callbacks).

TDD, stated honestly: the implementation of this card was written before its tests. It was then covered by unit tests, a contract suite run against both implementations, a counting-allocator test and mutation testing, and the review fixes below were each added with a test. This is a deviation from test-first for this card.

Independent review (fable, read-only): 0 blocker, 0 major, 9 minor. Fixed:
- Symlink or junction escape: `mount_dir` canonicalizes the directory and `os_path` canonicalizes the joined path and requires it to start with the mount, else `NotFound` (a Unix-only test creates the link; it did not run on Windows).
- Directory or growing file: opening a directory returns `NotFound` (Windows reports access denied); the file is opened first and measured from the open handle; `read_exact` is followed by a one-byte probe, and growth after measuring gives `Io`.
- `VPath` segments that are unsafe on Windows are refused: trailing dot or space, device names (`CON`, `NUL`, `COM1` ...) with or without extension, `* ? < > | "` and control characters.
- Docs said "makes no allocator call"; `read_take` frees the path, so they now say "gets no new memory". The allocation test checks allocations plus reallocations equal 0.
- Comment on the I/O thread: death is unreachable under `panic = abort`; the path is cloned on that thread, not the caller's.
- Test that an inner mount's miss does not fall back to the outer mount.
- `files_contract` strengthened: an empty file (`test/empty.txt`), two reads in flight with distinct buffers, buffer length kept and bytes past the file untouched.
- Note for the PR: `base` is a new runtime dependency of `platform`.
Not done: making `ReadRequest` an opaque newtype (optional; its fields are `pub(crate)` and it is documented as opaque).

Checks (local, Windows): fmt; Clippy pedantic `-D warnings` clean with and without `contract-tests`; `platform` tests green (54 unit, counting-allocator integration tests). Mutation (cargo-mutants 27.1.0) on `vpath.rs`, `files.rs`, `memory_files.rs`, `std_files.rs` after all fixes: 85 mutants, 49 caught, 25 unviable, 11 timeouts, 0 missed. The timeouts are all in the I/O thread loop (`io_loop`, `next_job`, `pop_job`, `finish`, `read_take`): a mutant there stops reads from finishing, so the contract wait loop never ends; they count as detected, not as survivors.
Not run locally: Miri (no unsafe), Linux (CI-only), branch coverage (nightly), line coverage, the symlink test (Unix only).

Open blocker/major: 0.
