# Review 2-8: headless-only CI job (governance)

Task: 2-8. Governance card (CI workflow), Class 3: goes to `main` first, one `ci` run started by hand on the commit to approve, then `develop` merges `main` in.
Loops: 1 of 3.
Reviewer: independent read-only subagent (general-purpose).

## Summary verdict

Ready for the owner. 0 open blocker, 0 open major.

## What the change does

- New job `headless` at the end of `.github/workflows/ci.yml`, Ubuntu only (the property is the same on every OS; Windows would bill double). Step 1: `cargo tree` of the workspace without `adapter_*` and `app_*`, over every target and every feature; the job fails if an excluded crate is still in the graph, and fails on an empty graph. Step 2: `cargo test --workspace --exclude 'adapter_*' --exclude 'app_*'`.
- A workflow test (`tools/release/test_workflows.py`) pins the job.
- Docs: `wiki/workflow/ci-diagrams.md` section 2 (Mermaid, five jobs), `wiki/README.md` v0.62.

## Exit criterion: what was missing

Roadmap phase 2: "banned-import + headless-only CI jobs green". Banned imports were already covered: arch-check (job `gates`, tool from `main`) refuses an engine crate that depends on an adapter (rule 4), on a banned crate or uses a banned `std` module. What was missing was a build-and-test proof with the adapters absent; that is this job. Not part of this card: the swap-diff check and the two-OS contract matrix (a Linux GLFW run is a separate question).

## TDD

Test first: red (`headless` job missing: ValueError), job added, green. After the review the test was tightened first (red: the flags `--target all --all-features` missing), then the workflow fixed (green). Negative proof by hand: a temporary dev-dependency of `base` on `app_runtime` made the graph step print the offender (reverted, `Cargo.lock` restored). Positive proof: graph clean and 387 + other tests pass without the excluded crates (on today's `main`, no `adapter_*` exists yet and cargo only warns that the pattern matched nothing).

## Findings

- Major, `cargo tree` saw only the runner's target and default features (a Windows-only or optional adapter dependency would pass): fixed with `--target all --all-features`, test and comments updated.
- Minor, the job test depended on `headless` being the last job and used a substring `if:` check: fixed (slice to the next job key, regex for a step condition).
- Minor, a glob that matches nothing (today's `main`) only warns in cargo: accepted, observed locally with the repo toolchain; the first run on the real runner is the evidence.
- Minor, `app_runtime` is excluded from this job but is tested in `g1`: intended (it is the L4 composition root).
- Minor, README jumps from v0.54 to v0.62: intended. `develop` already uses v0.55-v0.61; v0.62 avoids a clash when `main` is merged into `develop` (only the top of the list conflicts).
