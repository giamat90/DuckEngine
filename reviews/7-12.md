## Decisions

1. Every object is an entity (transform, sprite, and for falling bodies a physics body and a `Motion` record); one frame is the nine phases of `FramePlan`.
2. An impact is a velocity change of 3 m/s or more between two steps, because the physics crate reports no contact events. It queues a `SoundCue` (gain 0.2 to 1).
3. The render phase is a `Draw` trait object (coarse boundary), so tests use a recorder and the session uses the GL renderer.
4. The window run has no audio device: the frame mixes a block on the calling thread and the run is silent. A device is later work.
5. Own command line (the old one would print the old usage and accept `--scene`).

## Surviving mutants (12), stated, not hidden

- Window path (`draw_frame`, `run_window`, `run` in `app.rs`; `Renderer::resize` `||`): needs a GL window. The size decision was extracted into `plan_size` and is unit tested.
- `refused +=` in `find_impacts` and `run_phase` (4 mutants): the queue holds 64 cues and 80 bodies never hit in one step, so refusal is unreachable in normal play; the test asserts 0 refused.
- `Sandbox::set_execution` with `()`: the physics result is the same on any worker count, so only speed differs.

## Not verified

- Linux, and the window path with a real display and audio device (the binary test reports `not run` without one).
- Line and branch coverage (not measured locally; CI runs only on `main`).
- Reset frames are not measured for allocation (a reset builds a new world) and are not claimed.
- The replay hash covers physics state only, not the command stream, `Motion`, cues or the mix across worker counts.
