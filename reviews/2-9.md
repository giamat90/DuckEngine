## Findings

- Major (process), no migration step for `phase/2` and PR #82: fixed in the doc ("Transition"). PR #82 has meanwhile been merged into `phase/2`, so `develop` is created at the tip of `phase/2` and the branch deleted.
- Major (process), auto-delete of head branches could delete `develop` on the release merge: repository setting checked (`delete_branch_on_merge` is false), rule written (never `--delete-branch`, setting stays off).
- Major (process, unconfirmed by the reviewer), a stray `Release-Batch:` line in a card body: analysed; harmless for the version because a release is a minor bump anyway, still fails the release check if it lands in a governance squash. Written in the doc.
- Minor, `head.ref == 'develop'` ignored the head repository: fixed (`head.repo.full_name == github.repository`, test added). The extra `base.ref == 'main'` clause was not added (see TDD).
- Minor, fast-forward after a release can fail if a governance card landed meanwhile; sync merges to `develop` have no diff hash or approval; `develop` must contain `main` before a release PR: written in the doc.
- Minor, leftover wording in a test comment: fixed. Historical mentions of `phase/1` in reviews and the phase-1 audit are left on purpose.
- Not changed: the label format `YYYY-MM-DD` is a convention, not enforced (one word is). `merge commits` such as "Merge branch 'main' into develop" count as patch-level messages for `next_version.py`; they sit under the minor bump of the release.
