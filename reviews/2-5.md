# Review 2-5: fixed-step accumulator in the new `frame` crate

Task: 2-5. Class 2 (new public API, new crate). Card PR into `phase/2`.

Change: new crate `engine/frame` (workspace member) with `FixedStep::new(step_ticks, max_steps)`, `advance(frame_ticks) -> Steps { count, alpha, dropped }` and `FixedStepError`. Integer ticks (`u64`); `alpha` is a `u32` fixed-point fraction in `0..2^32` (rounded down); `dropped` is a `u128` tick total so that `u64::MAX` plus a remainder stays exact. Cap: at most `max_steps` steps, the surplus whole steps are dropped and reported, the sub-step remainder is kept. Tests: 14 unit tests, 4 property/loop tests (seeded `Pcg32`: conservation, repeatability, a headless loop on a manual tick counter, stall then recovery), 1 counting-allocator test (0 allocator calls). Core-runtime section with a Mermaid view, README v0.56. `base` is a dev-dependency only (the crate itself has no dependencies).

TDD: the 13 first unit tests were written against a stub (12 failed, red), then the implementation; review fixes added a literal-alpha test and a huge-step / after-cap alpha test.

Independent review (fable, read-only): 0 blocker, 1 major, 7 minor.
- Major, unreachable `unwrap_or` fallbacks in three narrowing conversions: accepted with a comment. The conversions cannot fail (remainder below a `u64` step, count at most `max_steps`, alpha below 2^32); the fallbacks only keep the function total and panic-free, the alternative being a lint allow. Mutation run: no missed mutant.
- Minor fixed: "depends on `base` only" wording (lib docs, wiki); alpha tests pinned with literals and a `step_ticks = u64::MAX` case and a post-cap case; `random_ticks` now asserts instead of silently truncating.
- Minor accepted: `u128` for `dropped` (kept for exactness, documented in the wiki); `panic!` in test helpers (same pattern as `base` tests, Clippy clean); determinism test is a same-process repeat, thread-count independence holds because `advance` has no threads.
